ARCHITECTURE SUMMARY
====================

The Quiet Advisor integrates three layers:

Layer 1: INFERENCE OBSERVATION
├─ Every inference logged automatically (no config)
├─ Captures: time, model, context, throughput, GPU state, quality
├─ Flows to: MemoryOS temporal graph + Advisor database
└─ Storage: memoryos.inference_log (time-series)

Layer 2: PATTERN DETECTION (Daily at 2 AM)
├─ 10 detector algorithms run in parallel
├─ Analyze yesterday's inference patterns
├─ Generate ranked insights
├─ Select top 1 card per user
└─ Store: quiet_advisor.cards table

Layer 3: CARD DISPLAY (Jupiter One UI)
├─ Show card on next login (if new)
├─ User can: act, dismiss, archive, learn more
├─ Actions trigger workflows in Apex-Metal
├─ Feedback trains personalization
└─ Dismissed cards inform ranking

Layer 4: LEARNING & ADAPTATION
├─ Track which cards user engages with
├─ Learn user's preference profile
├─ Bias detector selection toward preferences
├─ Personalization gets stronger over time
└─ Update: quiet_advisor.user_preferences


THE 10 DETECTORS
================

1. Context Waste Detector
   Detects: "You provided 8k context, used 2.1k (74% waste)"
   Saves: 2.5 hours/week typical

2. Model Thrashing Detector
   Detects: "You switched models 8 times, wasted 65 seconds"
   Saves: 3.5 minutes/day typical

3. Performance Envelope Detector
   Detects: "Your best hour was 1.6x faster. Here's why."
   Saves: 1.5 hours/week if replicated

4. Repeated Failures Detector
   Detects: "You've run this 4 times, failed all 4. Here's why."
   Saves: Hours of debugging

5. Quality Drift Detector
   Detects: "Your quality dropped 23% when GPU hit 81°C"
   Saves: Prevents shipping degraded outputs

6. Efficiency Frontier Detector
   Detects: "You're at 40% GPU efficiency. Batch 4 inferences = 3.2x"
   Saves: 1.5 hours/day at scale

7. Thermal Throttling Detector
   Detects: "Quality degrades when GPU >80°C. Set auto-throttle."
   Saves: 2-3 hours/week of debugging

8. Default Suboptimality Detector
   Detects: "You use Llama by habit. Qwen is 40% faster, same quality."
   Saves: 3 hours/week of wasted compute

9. Recency Bias Detector
   Detects: "You switched from Gemini (100% success) to Llama (92%)"
   Saves: Hours of failed attempts

10. Anomaly Detection
    Detects: "This inference took 3x longer. Here's why."
    Saves: Understanding your system better


HOW IT WORKS (DAILY CYCLE)
==========================

8 PM Previous Day:
  User runs 15 inferences
  Each inference automatically logged
  Data: model, context, throughput, GPU state, quality
  Stored in: memoryos.inference_log

2 AM (Batch Job):
  QuietAdvisorScheduler wakes up
  Queries: All inferences from yesterday
  Runs: 10 detector algorithms in parallel
  Ranks: Insights by time_savings, quality_improvement, novelty
  Stores: Top 1 card per user
  Completes: <5 minutes

8 AM Next Day:
  User opens Jupiter One
  CardDisplayService.get_card_for_user()
  Returns: Today's insight card
  UI shows: Quiet, not intrusive
  User sees: "PATTERN DETECTED: Context Waste"

User Interaction:
  [Try reduced context] → Triggers Apex-Metal config change
  [Dismiss] → Card fades, logs dismissal
  [Archive] → Never show this type again
  [Learn more] → Opens deep dive explanation

System Learning:
  CardActionHandler tracks what user does
  Updates: quiet_advisor.user_preferences
  Biases future detections toward user preferences
  Over time: Cards get more relevant, higher engagement


DATABASE SCHEMA (3 NEW TABLES)
=============================

Table 1: quiet_advisor.cards
├─ Stores: Generated insight cards
├─ Columns: id, user_id, detector_type, title, description, metrics
├─ Columns: recommended_action, action_value, time_savings_seconds
├─ Columns: user_dismissed, user_archived, user_actioned
├─ Retention: 7 days active, then archive
└─ Indexes: (user_id, created_at DESC)

├─ Stores: User interactions with cards
├─ Columns: id, card_id, user_id, action_type, action_result, created_at
├─ Actions: 'view', 'dismiss', 'archive', 'learn_more', 'action'
├─ Used for: Learning user preferences, measuring impact
└─ Indexes: (user_id, created_at DESC), (card_id, action_type)

Table 3: quiet_advisor.user_preferences
├─ Stores: Learned user preferences
├─ Columns: user_id, card_type_preferences (JSON)
├─ Format: {"context_waste": 0.9, "efficiency_frontier": 0.7, ...}
├─ Values: 0-1 (0=don't care, 1=love these cards)
├─ Used for: Ranking insights by user preferences
└─ Indexes: (user_id) unique


MEMORYOS INTEGRATION
====================

How Quiet Advisor connects to MemoryOS:

1. Inference Log → Temporal Graph
   Every inference logged in memoryos.inference_log
   Links to MemoryOS temporal graph for heat score calculation

2. Insight Annotations
   MemoryOS models get labeled with Advisor insights
   Example: Model thrashing detected → suggest warm tier caching

3. Tier Assignment Enhancement
   Detectors inform MemoryOS tier routing decisions
   Example: Two models same heat, but user thrashes between them
           Keep both in Warm (costs RAM, saves time)

4. Context Extension Hook
   When Advisor suggests context reduction, MemoryOS adjusts
   When suggests context extension, MemoryOS activates hybrid KV

5. Checkpoint Management
   Advisor suggests models to keep cached
   MemoryOS allocates NVMe checkpoints accordingly

APEX-METAL INTEGRATION
======================

How Quiet Advisor talks to Apex-Metal:

1. Inference Hook
   After every inference completes, Apex-Metal calls:
   ApexMetalHook.post_inference_hook(result)
   Passes: model_id, context, latency, throughput, GPU state, quality

2. Config Updates
   When user clicks [Try reduced context]:
   Apex-Metal receives: {"context_tokens": 2048}
   Applies to next inference run

3. Model Swapping
   When user clicks [Switch model]:
   Apex-Metal loads alternative model
   Runs same prompt on both
   Returns side-by-side metrics

4. Performance Measurement
   Advisor tracks before/after for every action
   Stores impact data in quiet_advisor.card_actions
   Learns which optimizations work for which users
